## Daily merge: GitHub Action vs box script — recommendation
**Recommend: box script (cron on the box) for merge+build, with a PR-based publish via a scoped token — not a GitHub Action for the merge.**
- Inbox files land on the box; an Action can't see them unless they're committed first, which means the box needs push rights anyway,
  and raw unvalidated scraped records would land in repo history.
- Box flow: `cron 06:00 CT → node scripts/merge-inbox.mjs → node scripts/validate.mjs && node --test test/ → (publish)`. Publish = commit to a branch and open a PR (fine-grained token, contents+PRs on this repo only), auto-merge optional once trusted.
- Add a tiny **scheduled GitHub Action** that only runs `node scripts/build.mjs && validate` daily on main and commits if expiry dropped pages
  — so expired jobs are removed even if the box is down (Google penalizes stale postings more than missing ones).
- Tradeoffs: box = single point of failure, needs a credential on the box, but validates before anything is public. Action-only = reliable scheduling and audit log, but requires committing inbox files (or an upload channel) and does validation after data is already in the repo.

## Risks (Google job posting policy)
- **Expired jobs**: all validThroughs are a guessed default (posted+60d). If a role closes earlier, we still mark it open → policy violation / manual action risk. Need real close dates or periodic link checks of applyUrl.
- **Must match visible content**: JSON-LD is generated from the same record as the page; but metro-claims-rep lists Philadelphia from "Greater Philadelphia", and "Remote & regional" (aaa-pa) is asserted as US-remote — confirm.
- **Not single jobs**: aaa-pa ("Public Adjuster / Sales / Support roles") and statewide-pa are careers-page pointers, not one posting. Google forbids JobPosting on listing/multi-job pages; I'd set `jsonld:false` on aaa-pa too (left on pending your call). fapia-board is already excluded by rule (type "Various").
- **directApply false** is correct (all apply off-site).
- **Aggregated/scraped listings & attribution**: inbox records require `sourceUrl`; page shows "Originally posted at" link when it differs from applyUrl. Copying employer description text verbatim may raise copyright issues; Google also tends to prefer the original employer posting (our page may be treated as duplicate). Rewrite/summarize descriptions and keep attribution.
- **Thin/duplicate content**: 3-paragraph descriptions are thin; near-identical listings across ids get flagged by merge but not dropped.
- **Removal**: removed jobs return 404 on GitHub Pages (fine); a Search Console manual action for job posting spam can remove all job rich results site-wide.
- `_gen/regen_jobs_ctj.py` still exists and would overwrite pages without validThrough if run — retire it.
- Board fetch now depends on `jobs.active.json`; deploy both together (cached old main.js still works since `jobs.json` remains).
